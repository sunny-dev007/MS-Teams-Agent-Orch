High-Level Design (HLD)

The platform follows a webhook-driven, event-sourced architecture where WhatsApp and Gmail push events into the FastAPI server, which delegates work to a LangGraph state machine containing specialized AI agents. The system is designed for a single-user personal deployment with enterprise-grade patterns.

Agent Orchestration Flow

The platform implements six distinct conversational workflows, each routing through the LangGraph state machine from a single entry point (the Planner).

Flow 1: General Conversation

WhatsApp Message → Planner → General Agent → Notify (Reply)

Flow 2: Email Read / Send

WhatsApp → Planner → Email Agent → Evaluator → Notify

Flow 3: Code Development (Full Pipeline)

WhatsApp → Planner → Repo Wizard → Developer → Reviewer ↔ Approval (WhatsApp) → Deployer → Live

Flow 4: Calendar / Meetings

WhatsApp → Planner → Calendar Agent → Event Created + Notify

Flow 5: Repository Browsing

WhatsApp → Planner → Repo Wizard ↔ Multi-turn (Provider → Project → Repo) → Ready

Flow 6: Human Approval & Deploy

APPROVE task-xxx → CI Gate Check → Resume Graph → Deployer → CI Watch → Evaluation
Human-in-the-Loop: The code development pipeline pauses at the approval stage, persists state to SQLite via LangGraph's AsyncSqliteSaver, and resumes when the user sends APPROVE <task-id> or REJECT <task-id> via WhatsApp.

The system uses a two-layer architecture: Specialists (graph-wired wrappers in specialists/) delegate to Agents (business logic in agents/).

WhatsApp Permanent Token (System User)

The temporary developer token expires every 24 hours. For production, create a permanent token:

  1. Go to Meta Business Suite → Settings → Business Settings
  2. Under Users, click System Users → Add
  3. Name: "AI Agent", Role: Admin
  4. Click Add Assets → select your WhatsApp app → toggle Full Control
  5. Click Generate Token → select whatsapp_business_messaging and whatsapp_business_management
  6. Copy the token into WHATSAPP_ACCESS_TOKEN — this token does not expire

Google OAuth Scopes Setup

  1. Go to Google Cloud Console → Google Auth Platform → Data access
  2. Add these scopes:
    • https://www.googleapis.com/auth/gmail.readonly
    • https://www.googleapis.com/auth/gmail.send
    • https://www.googleapis.com/auth/calendar.events
  3. Create Desktop type OAuth 2.0 credentials (not Web)
  4. Run the setup script and complete the browser flow

Developer Guide

Code Flow Walkthrough

Tracing a WhatsApp message from arrival to response:

1. Message Arrival

api/whatsapp.py receives the POST webhook. It verifies the HMAC-SHA256 signature using core/security.py, checks the phone allowlist, and parses the message payload via services/whatsapp.parse_incoming_message().

2. Approval Check

The message text is matched against APPROVE_PATTERN / REJECT_PATTERN regex patterns. If matched, the CI gate is checked (services/ci_gate.py), then resume_graph() is called with a LangGraph Command(goto="handle_approval") to resume the paused graph.

3. New Message Handling

For non-approval messages, core/background.py:handle_whatsapp_message() runs as a FastAPI BackgroundTask:

  1. Fast-path check: If the message is a simple greeting (regex match in planner/agent.py:is_simple_greeting()), respond immediately from core/persona.py:GREETING_REPLY without loading the graph
  2. Instant ack: Send "Working on it..." to WhatsApp so the user sees immediate feedback
  3. Graph execution: Call agents/graph.py:run_graph() which builds, compiles (with SQLite checkpointer), and streams the LangGraph

4. Planner Node

planner/agent.py:plan() runs first:

  • Checks ConversationSession for in-progress multi-turn flows (repo wizard, meeting, pending approval)
  • Regex fast-paths for known patterns: "check email", "schedule meeting", "check repos", "task status"
  • Falls back to LLM classification using prompts/router_classify.txt
  • Returns AgentState with intent set for conditional routing

5. Conditional Routing

_route_after_plan() maps the intent to the appropriate specialist node. Each specialist wraps the underlying agent logic and tags handled_by.

6. Code Development Pipeline (example)

  1. Developer Agent → clones repo via git_ops, builds LLM prompt from repo tree + task, parses JSON file changes, applies to workspace
  2. Notify → sends diff preview to WhatsApp
  3. Reviewer Agent → LLM reviews with severity scoring, may loop back to developer (max 3x)
  4. Request Approval → formats change preview, sends to WhatsApp, graph pauses at END
  5. Resume → user sends APPROVE, graph resumes at handle_approval
  6. Deployer Agent → commits, pushes, creates PR, optionally merges, triggers pipeline
  7. CI Watch → background poller monitors pipeline to completion
  8. Evaluator → generates step-by-step summary sent to WhatsApp

Security Design

Webhook Authentication

HMAC-SHA256 signature verification on every WhatsApp POST webhook using the App Secret. Prevents spoofed messages.

Phone Allowlist

Only phone numbers in ALLOWED_PHONE_NUMBERS can interact. Empty list = allow all (dev mode).

OAuth2 (Google)

Refresh tokens stored in App Settings (encrypted at rest). No interactive flow at runtime — token generated once via setup script.

API Tokens

GitHub PAT, Azure DevOps PAT, WhatsApp token — all stored as SecretStr in pydantic-settings, never logged or serialized.

CI Gate & Deploy Locks

Provider-isolated async locks prevent concurrent deploys to the same repo. CI busy check blocks approval until pipeline completes.

Human-in-the-Loop

No code is pushed without explicit APPROVE <task-id> via WhatsApp. Rejection stops the pipeline immediately.
